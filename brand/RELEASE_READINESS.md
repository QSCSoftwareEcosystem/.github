# Release-readiness checklist

This checklist is intentionally separate from the
[repository branding guide](README.md). A repository can be a successful
branding pilot while some or all of these items remain open.

Use this checklist when a project is preparing for public distribution,
versioned release, or a support commitment.

## Governance

- Approved license and matching package metadata
- Preferred citation and `CITATION.cff` when applicable
- Approved funding acknowledgment and public-release language
- Security and vulnerability-reporting policy
- Named maintainers and an escalation path

## Validation

- Installation tested in a clean environment
- Supported platforms and dependency versions documented
- Required tests and scientific validation passing
- Reproducible examples or archived benchmark evidence
- Optional integrations tested in the environments claimed as supported

## Release and support

- Versioning and compatibility policy stated
- Release artifacts, documentation, and changelog prepared
- Maintenance and user-support expectations stated
- Scientific-lead and program-level review completed when required
- Archival or deprecation path identified

Completing this checklist does not replace institutional legal, cybersecurity,
export-control, publication, or communications review.
